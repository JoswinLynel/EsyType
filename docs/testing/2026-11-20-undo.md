## Problems found and fixed during testing

| Problem | Fix |
|---|---|
| **The typing-since guard did not run:** the global keyboard/mouse hooks need the program's module handle; without it Windows refused them silently, and Undo went ahead after the user typed (in the test it undid the typed "q" instead of the dictation) | Hooks installed with the module handle; if they cannot be installed, Undo is refused ("EsyType cannot tell whether you typed since, so it will not guess") |
| **The guard kept only the latest input:** the Undo shortcut's own key press replaced the earlier typing, so typing-then-Undo was allowed | The guard keeps the *first* key press or click after the dictation; only one at the moment of the request is allowed |
| Pressing a pill button through UI Automation (as a screen reader can) activated the pill, so the window check failed | The pill is a no-activate window at the Windows level; if EsyType's own window is in front anyway, focus is handed back to the dictated-into window (one marked Alt tap, which Windows requires) before checking; another program the user chose is never taken over |
| The test copy has several windows titled "EsyType recording" (some hidden) | Test helper lists visible windows only |

## Differences from the plan

| Plan | Built | Why |
|---|---|---|
| "No key presses or clicks since (Windows' last-input time)" | Keyboard and mouse hooks for the minute after each dictation, recording only the time of the first key press (not modifier keys) or click | Windows' last-input time also changes when the mouse moves (so moving to the pill would refuse Undo) and keeps only the latest input |
| Terminals by program name | Consoles and terminals recognised by window class (not title), plus an editable program list | A WinForms program hosted by powershell.exe is not a console |
