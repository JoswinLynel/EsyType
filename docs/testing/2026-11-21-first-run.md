# Phase 5, Milestone 2: First-run wizard. Test record

**Date:** 21 November 2026 · **Plan:** `docs/plans/first-run-plan.md` (approved by the owner with shortcut option A) · **Builds:** e2e test build (separate folder), then the installed production copy · **Nothing downloaded from the internet; no dependency added**

## What was built

- **Setup wizard** (`src/setup.tsx`), eight steps: Welcome, Privacy (one switch: Keep History), Speech model (this PC's processor, memory, storage, AVX2 and the three cards), Download, Microphone, Shortcut, Try it, Ready.
  - Step counter, Back on every step, a fixed header and buttons with only the step scrolling (works at 200% zoom and at the minimum window size).
  - Continue is allowed while the model downloads; Try it waits for it.
  - Finish saves the setup and hides the window to the tray. **Run setup again** in Settings → About walks through it again without deleting anything.
- **When it appears** (`settings.rs` `settle_setup`): a new `setup_done` setting. Missing (a settings file from before this milestone) → decided at start-up: a model installed, or a settings file that exists but cannot be read, means an existing user, so no wizard. Decided in memory only and written at the next save: **starting never rewrites `settings.json`**. A PC that is not set up opens the window even when started with `--minimized`.
- **Recommendation** (`hardware::recommend`): Base, or Tiny when Base does not fit the free memory or storage; never Small automatically; none when nothing fits (the step says why).
- **Download step:** progress, MB, speed and time left, Cancel, Retry (resumes), "Checking the file (SHA-256)…", "Verified". Errors in words (server unreachable, integrity check failed).
- **Microphone test** (`mic_test`): 3 seconds, a live level bar, "We heard you" / "Very quiet…" / "Nothing heard…". Nothing kept or transcribed. Thresholds from typical speech levels, not yet checked on other microphones (marked in the code).
- **Shortcut capture** (`KeyCapture`, also in Settings → Shortcuts, replacing the typed fields):
  - press the keys, then **Use this**; Esc or Cancel ends it; Tab moves to the buttons
  - EsyType's own shortcuts are paused while capturing (`pause_shortcuts`) and restored on Use, Cancel, Esc, the window really losing focus, or after 20 seconds by EsyType itself
  - refused with a reason (`shortcut_problem`, checked again on save): Win-key combinations, a single key other than F1–F24, Shift with a key, Esc, Alt+Tab, Alt+F4, Alt+Space, Ctrl+Alt+Delete
  - works with input that has no hardware scan code (remote desktops, on-screen keyboards)
- **Decision 0009:** Ctrl+Space kept (owner, option A); the shortcut step names its known clashes. The decision record and system design were corrected: holding Ctrl+Win alone is not supported by the build.

## Fixed on the way

- **Changing one shortcut failed if another program held the other one.** Saving re-registered both the hold-to-talk and start/stop shortcuts, so with your installed EsyType holding Ctrl+Shift+Space, the test build could not change Ctrl+Space to anything. Now only the changed shortcut is re-registered.
- **First versions of this milestone, found by the tests before release:**
  - an unreadable settings file showed the wizard instead of the recovery banner
  - starting rewrote an older settings file (the History UI suite checks it does not)
  - the capture box ignored keys sent without a scan code
  - a click on **Use this** could restart the capture instead of saving: the click briefly blurred the window, which ended the capture, and React reused the same button as **Change**
  - at 200% zoom the pinned buttons floated over the step
